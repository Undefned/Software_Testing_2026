# Тест-кейсы и сценарии использования (Tutu.ru, раздел Ж/д)

Объект проверки: `https://www.tutu.ru/poezda/` — форма поиска ж/д билетов и страница
результатов. Разделы Авиа, Отели, Автобусы, Аренда авто на tutu.ru не тестируются.

## Запуск в двух браузерах

Каждый сценарий в `TutuE2ETest` параметризован через
`@ParameterizedTest` + `BrowserTypeProvider#allBrowsers()`:

- `mvn test` — без `-Dbrowser` провайдер отдаёт **и Chrome, и Firefox**; вместе с
  `src/test/resources/junit-platform.properties` (параллельное выполнение JUnit 5,
  `fixed`-стратегия на 2 потока) оба браузера реально стартуют **одновременно** в разных
  потоках в рамках одного прогона.
- `mvn test -Dbrowser=chrome` / `mvn test -Dbrowser=firefox` — точечный прогон в одном
  браузере, если нужно отладить конкретный сценарий без параллелизма.

По умолчанию все браузеры запускаются в headless-режиме (без видимого окна) — иначе при
18 сценариях × 2 браузера параллельно экран буквально забивается открывающимися окнами.
Чтобы увидеть происходящее глазами при отладке конкретного теста:
`mvn test -Dtest=TutuE2ETest#e2e03SearchWithChild -Dheadless=false`.

## Глубина покрытия

Проверяются устойчивые пользовательские состояния интерфейса, а не нестабильные внешние
данные (конкретная цена, номер поезда, время в пути, рейтинг, количество отзывов,
количество свободных мест).

**Полностью тестируется (E2E):** маршрут, дата, пассажиры, запуск поиска, фильтры
результатов, сортировка, валидация формы.

**Тестируется поверхностно:** кнопка «Выбрать места» на карточке поезда — только факт
перехода, без самого процесса бронирования; ссылка «Маршрут» — аналогично.

**Не тестируется:** «Оформляйте сейчас, платите потом», блок рейтинга/отзывов, конкретные
цены и номера поездов, переключатель «Искать отели в новой вкладке».

**Прошедшие/неактивные даты в календаре.** Тесты написаны 30 августа 2026 года. Любая
дата раньше момента написания тестов считается заведомо неактивной и отдельно не
проверяется. Активной датой в тестах всегда выбирается последняя доступная ячейка в
открытом месяце календаря.

**Возраст ребёнка при добавлении пассажира (E2E-03).** Существование и разметка попапа
выбора возраста ребёнка **не подтверждены одинаково в Chrome и Firefox** — в HTML-дампе,
снятом вручную, уже добавленный ребёнок сразу имел возраст «7 лет» без видимого шага
выбора. Поэтому `TutuHomePage.addChild()` не считает отсутствие такого попапа ошибкой:
если он появляется — выбирается первый доступный вариант; если нет — тест продолжает
работу с тем возрастом, который сайт проставляет сам. Это осознанный компромисс, а не
баг теста: жёстко завязываться на неподтверждённый в обоих браузерах элемент интерфейса
было источником нестабильности (тест падал по таймауту только в Firefox).

## Известные допущения в локаторах

- Оба поля ввода города («Откуда»/«Куда») скоупятся через соседний
  `span[@data-ti='input-label']` с текстом метки.
- На странице присутствуют два элемента `button[@data-ti='swapButton']` (мобильная и
  десктопная версии) — код кликает по первому видимому.
- Активная ячейка календаря определяется отсутствием вложенного маркера
  `calendar-day-cell-price-empty`; кликается последняя доступная ячейка в открытом месяце.
- Попап выбора возраста ребёнка (E2E-03) — необязательный шаг, см. раздел «Глубина
  покрытия» выше.
- NEG-02 проверяется через отсутствие несуществующего города в подсказках автокомплита,
  а не через css-класс ошибки — это устойчивее к смене вёрстки.
